## Scope note (not a defect)
`useAsync.ts`, `ErrorMessage.tsx` and `Pager.tsx` sit in `src/components/`, outside FE-03's listed paths but inside FE-owned `src/components/`; `src/vite-env.d.ts` is a type declaration. All are generic and reusable by FE-05, with nothing sources-specific, and they are exercised by the page tests:
- `useAsync` aborts the previous request on dependency change or unmount, ignores results after abort, maps non-`ApiError` failures to `network_error`, and has a `reload`. The one `eslint-disable react-hooks/exhaustive-deps` is justified by the intentional `[...deps, tick]` dependency list. It has no direct unit test; retry, loading and error are covered through the page tests.
- `ErrorMessage` and `Pager` are small and correct.

## Needs ruling (not a code defect)
- **`VITE_MAX_UPLOAD_MB`.** It is an optional build-time env var (default 100, matching `LOCALETL_MAX_UPLOAD_MB`'s default) read in `uploadRules.ts` and typed in `vite-env.d.ts`. It is **not** in `.env.example` or architecture §4, and CLAUDE.md makes `.env.example` the binding variable list. The user decides whether to add it there or to replace it with a constant. Note that a frontend build-time variable can silently differ from the server's runtime `LOCALETL_MAX_UPLOAD_MB`; the server stays authoritative either way.
