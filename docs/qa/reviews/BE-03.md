## Needs ruling / proposed contract change
1. **Contract gap (orchestrator-owned file):** `getSource` and `deleteSource` declare only 200/204, 404 (and 409) but a malformed id such as `/sources/not-a-uuid` returns 422 `validation_error`, the correct contract `Error`, which the contract does not list for those two operations (it does for `previewSource`). The harness checks this case as a global error. Suggest adding the `ValidationError` response to `getSource` and `deleteSource`.
2. `previewSource` returns 500 `internal_error` if the stored file is missing; 500 is not declared. It is a proper `Error` body and does not leak the path (tested).
3. The error `path` for form faults is the bare field name (`file`, `delimiter`, …) as accepted by the orchestrator.

## Defects
None. Info:
- A NUL character inside a cell is accepted at upload (confirmed: 201) and would fail the run at load (ETL-06 `LoadError`); see the ETL-02 review.
- If the process dies mid-upload, a partial file stays in `tmp/` (nothing removes old ones at startup).
- The full-file `inspect_csv` pass runs in a thread pool, so a very large upload does not block the event loop.
