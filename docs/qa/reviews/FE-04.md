## Defects (both confirmed in a scratch copy)
1. **Low-medium: a valid datetime range can be blocked.** The `min <= max` check compares ISO strings lexicographically, but the accepted forms allow `T` or a space as the separator, and `T` (0x54) sorts after a space (0x20). `min: "2026-01-01T10:00"`, `max: "2026-01-01 11:00"` is valid (10:00 ≤ 11:00) yet reports "The minimum must not exceed the maximum", and the form refuses to save. The mirror case (`min "2026-01-01 10:00"`, `max "2026-01-01T09:00"`) passes the client although min > max (the server's validate would catch it). Fix: normalise the separator, or compare parsed dates.
2. **Low: integers above 2^53 are silently altered.** `parseScalarInput("9007199254740993", "integer")` returns `9007199254740992` (via `Number`), so the config sent differs from what was typed. `isIntegerText` itself uses `BigInt` and accepts up to the bigint limit, so the typed text is accepted and then rounded. Related info: a JS number `2**63` passes `isCastableConfigScalar` and the integer range-bound check (precision), although the server rejects it as out of bigint range; advisory only because the server stays authoritative.
