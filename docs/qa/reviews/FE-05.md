## Defect
**1. Medium: the rejections table can stay empty after a live run finishes.** `RunDetailPage` refetches the rejections only when `[runId, offset, run.rejected_count]` changes. But architecture §7.2 persists rejection rows only at the end of a run (success: "insert `rejected_sample` into `run_rejections`" in the final transaction; failure: "insert rejection entries received so far"), while the counters, including `rejected_count`, update on every stage event. So while the run is `running` the endpoint returns no entries even though `rejected_count` is above 0, and when the run becomes terminal `rejected_count` is usually unchanged from the previous poll, so nothing triggers a refetch.
- Repro (scratch copy, same harness as `RunsPage.test.tsx`, fake timers): polls 1-2 return `running` with `rejected_count: 1`, and `GET /runs/{id}/rejections` returns `items: []` until the third poll; poll 3 returns `succeeded` with `rejected_count: 1` and the rejections endpoint now returns one `type_cast` entry. Result after the run finished: status "Succeeded", the entry is **not** shown, and "No rejected rows." is displayed, although the counter says 1.
- Effect: a user who starts a run and watches it sees a wrong, empty rejections section until they reload the page. This is the main monitoring flow.
- Suggested fix: include the run status (or `isTerminal(run.status)`) in the dependency list so the table refetches once when the run turns terminal; add a test like the repro above. Optionally show "Rejected rows are listed when the run finishes" while the run is active and `rejected_count` > 0.
- The existing live-polling test does not catch it because the rejections mock returns the same data throughout.

## Notes (info)
- Each rejections refetch replaces the table with "Loading rejections…" (the shared `useAsync` resets to loading), which flickers as the live count changes.
- Polling continues on non-404 errors indefinitely at 2 s; a back-off would be kinder to a stopped API.
- The run list shows the counters per run as text from the same five fields.
